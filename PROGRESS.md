### 8. Findings that affect later design
- **`dataset_npy/*.npy` are pickled dicts**, not plain masks: `data` = (938, 1783, 12) float64 raw digital numbers (imagery), `label` = (938, 1783, 1) binary ship mask (0/1). Unpickling can execute code, so `load_pickled_npy` disassembles the pickle first and refuses anything except numpy array internals (all 16 files passed). The pickle is touched only once, by `prepare_tiles.py`; everything downstream reads plain arrays.
- **Band order mismatch:** the npy channel order is `B01,B02,B03,B04,B05,B06,B07,B08,B09,B11,B12,B8A` (B8A last). The project's canonical order is Sentinel-2 wavelength order (`B8A` after `B08`). `prepare_tiles.py` reorders and verifies every channel of every tile bit-for-bit against the per-band GeoTIFFs. Always index bands by name via `src/data/bands.py`.
- **Water masks are on a different grid:** 938×1784 at 10.000 m versus imagery 938×1783 at 10.0048 m (same origin and extent). Resampled with nearest-neighbour onto the imagery grid rather than cropped, because a crop would drift up to about 0.9 pixel at the right edge.
- **Tiles overlap spatially (threat to tile-level splits):** `suez1`/`suez2` overlap by 93.6% (near-duplicate scenes from the same day); `rotterdam1`/`rotterdam2` by 6.9%; `rotterdam2`/`rotterdam3` by 13.9%. The other tiles are independent. Overlapping tiles must never sit on opposite sides of a train/val/test split, or the test set leaks.
- **Ship distribution is very uneven:** `toulon` has 263 of the 1,053 ship polygons; `suez1`–`suez4` have 5–8 each. `rotterdam1` has the most ship pixels (10,957). Folds should be balanced on ship counts, not just tile counts.
- **Ship pixels mostly lie on the water mask** (94–100% for most tiles) but less for `rome` (68%) and `marseille` (81%), likely ships in port. Relevant when interpreting ship-vs-water metrics (E5).
- Water fraction varies widely (2% for `suez1`/`suez2` up to 84% for `portsmouth`).

### 9. Fold splits (`scripts/make_splits.py`, `src/data/splits.py`, `configs/splits.json`)
Tile-level 4-fold cross-validation: 10 train / 2 val / 4 test tiles per fold, every tile is a test tile exactly once.
- **Overlap groups are computed from the tile bounds, not hard-coded:** `{rotterdam1, rotterdam2, rotterdam3}` and `{suez1, suez2}`. A group is never split across train/val/test within a fold. Since the rotterdam trio needs 3 of the 4 test slots, it necessarily forms one test set together with one other tile.
- **Test sets:** all packings of whole groups into 4 equal test sets are searched exhaustively (17,325 candidates); the chosen one minimises the coefficient of variation of ship polygons plus that of ship pixels across the 4 test sets. Val pairs are then picked per fold to have about half a test set of ship polygons, spreading val use across tiles. The seed only orders the folds and breaks ties; the test partition itself is determined by the optimisation.
- **Result (seed 0):** test ship polygons per fold are 266 / 247 / 278 / 262 (well balanced). Test ship pixels are not balanced (6,319 / 17,876 / 3,934 / 6,211) because `rotterdam1` alone has 10,957 ship pixels and the rotterdam trio is forced into one test set (fold 1). Expect fold 1's test metrics to be dominated by rotterdam.
- **Verification:** `python scripts/make_splits.py --check` re-validates the saved file (each tile tested once, splits disjoint and complete, no overlap group split). A deliberately leaky split (suez1 in val, suez2 in train) is rejected by the validator.
- Scene-level similarity beyond spatial overlap is not controlled for. Non-overlapping neighbours: `portsmouth`/`southampton` are 4.4 km apart (same date, in different folds' test sets); `suez3`–`suez6` are 14–18 km apart (same date). No shared pixels, but shared scene statistics; state this as a limitation.

### 12. Degradation engine (`src/degrade/`, `scripts/compute_signal_stats.py`, `scripts/check_degradation.py`)
- **SNR definition:** `SNR_b = 10·log10(P_b / N_b)`. `P_b` = mean square of band `b` over the tile's **valid pixels** (not 0, not saturated at 65535), computed once per tile and band (`data/processed/signal_stats.json`, git-ignored, regenerate with the script). `N_b` = average noise power added to the band. Mean square (not variance) is used, so the mean intensity dominates `P_b`.
- **Effect of excluding invalid pixels:** naive `P_b` would be inflated by up to 3.24 dB (`panama` B09), 2.85 dB (`rotterdam2` B09), 2.13 dB (`rotterdam3` B01); under 0.03 dB for the 13 clean tiles.
- **Noise types**, both scaled to the same `N_b` so a nominal SNR is comparable across them: `gaussian` (`y = x + n`, `n ~ N(0, N_b)`) and `poisson_gaussian` (`y = a·Poisson(x/a) + n`, gain `a = ρ·N_b / mean_b`, read noise variance `(1−ρ)·N_b`, so pixel variance `a·x + (1−ρ)·N_b` averages to `N_b`). `ρ` (`shot_fraction`) is **assumed 0.5, not calibrated to the sensor**; it is logged with every degradation and is the knob for E2/A9.
- **Design choices:** noise is added everywhere, including saturated and zero pixels (those pixels must be masked in metrics and loss later). Output is float32 in raw DN units and **not clipped**, so the realised SNR is not distorted at low signal (clipping would be a further assumption). SNR can be a scalar or per band (needed for the A5 conditioning ablation). `degrade()` returns the noisy patch plus a params dict (noise type, seed, per-band SNR, σ, gain, read σ, ρ) that maps directly onto the planned `degradations` table.
- **Seeding:** `degradation_seed(base_seed, id, key)` uses SHA-256 (stable across processes and platforms, unlike Python's `hash`). **Superseded in step 15:** test noise is now generated per tile (not per patch) at 9 levels 0-40 dB with three noise types, and the training range is 5-40 dB.
- **Verified on real tiles** (`toulon`, heavily saturated `panama`, zero-pixel `rotterdam3`; both noise types at 0, 10, 30 dB): realised SNR is within 0.015 dB of target in every band (tolerance 0.1 dB). Poisson-Gaussian noise is signal dependent (noise power in the brighter half of B08 is 1.60× the darker half), Gaussian is not (1.00×). Same seed gives identical noise, different seeds differ, per-band SNR arrays are honoured.
- **Not covered:** the "clean" reference is itself a real, already noisy image; realised SNR is relative to that reference (a threat to validity in the doc). Noise is spatially and spectrally independent, which real sensor noise may not be.

### 14. Methodology review before the research phase (2026-09-19)
Checked against the data (A, B) and ESA's published SNR requirements (C). None of these are code bugs; they are threats to what the paper can claim.
- **(C) "Realistic noise" framing.** ESA's requirements at reference radiance give amplitude SNR of about 154 (B02), 168 (B03), 142 (B04), 174 (B08), 100 (B11, B12). In this project's convention (`10·log10(P_b/σ²)`, i.e. `20·log10` of the amplitude ratio) that is about 40–45 dB. Our test range is 0–30 dB (train 5–30 dB), so it is a **stress-test regime worse than nominal sensor noise**, not "realistic". Darker targets such as water have lower real SNR, so the low end is not absurd for ships on water, but the title/abstract wording must change or the range must extend to 35–40 dB. Values are from web search results (ESA Sentinel Online / SentiWiki); confirm in the ESA User Handbook before citing. Our `P_b` (tile mean square) is also not identical to ESA's `L_ref` definition.
- **(A) iid white noise on very smooth bands.** Gradient-energy ratio `r = mean(dx²)/(2·var)` (white noise = 1): native 10 m bands 0.010–0.074; resampled bands 0.0004–0.014 (`B09` 0.0004–0.0008, `B01` 0.001–0.002). Every band carries at most about 7% of white-noise high-frequency energy, so pixel-wise iid noise is spectrally far from the signal and denoising is easier than for real sensor noise (ceiling effects). The native/resampled split is not clean (`B08` is as smooth as `B05`). Consequences: H2 (spectral block helps) and ablation A6 (4 vs 12 bands) may show small or misleading effects; consider a spatially correlated noise variant or say so as a limitation.
- **(B) Nominal SNR is tile-relative, so ship visibility varies about 7× at the same SNR.** Per-pixel contrast-to-noise (ship vs nearby water) in B04 at 10 dB: `brest1` 3.56, `portsmouth` 2.58, `rotterdam1` 1.98, `toulon` 1.96, `panama` 0.49 (B08: 1.16–1.50, `panama` 0.52). At 0 dB most tiles are below 1 (`panama` 0.04–0.16). So low-SNR ship failures can be physical limits rather than model failures, and RQ3 must be reported against measured ship contrast-to-noise, not only nominal SNR.
- **Test noise per patch versus per tile (fixed in step 15).** The first design seeded noise per patch, so overlapping patches carried different noise on the same pixels, which rules out consistent full-tile noisy images, stitched evaluation and clean/noisy/reconstructed figures.
- **Bootstrap over ship instances must be clustered by tile.** Ships within a tile share scene and noise (`toulon` alone is 25% of the 1,053); a plain bootstrap over instances gives intervals that are too narrow. Use a hierarchical bootstrap (tiles, then ships).
- **Effective sample size is below 16 tiles.** `suez1`/`suez2` are near-duplicates, the rotterdam tiles overlap, and several tiles share date and region (about 13 independent groups). Per-tile Wilcoxon tests need care and a multiple-comparison correction (Holm) across experiments and SNR levels.
- **Evaluation harness must define:** PSNR peak (a fixed 65535 peak inflates PSNR because reflectances are low; use a per-band or per-tile robust peak and report normalised RMSE); averaging over overlapping patches versus full-tile stitching; masking of saturated and zero pixels in metrics and loss.
- **Small validation set:** 2 tiles (about 130 ships) chooses the best checkpoint and drives baseline tuning, so selection is noisy; the SNR at which validation is scored must be fixed.
- **Narrow data:** 16 scenes from 9 areas, all April 2021; generalisation claims are limited (E7 helps only for global image quality, BigEarthNet has no ship labels).
- **Unchanged assumptions already recorded:** the clean reference is itself a noisy real image; Poisson-Gaussian shot fraction 0.5 is not calibrated; ship labels are tiny (about 6 pixels per ship).

(The estimator uses only native bands; resampled bands would be biased low.)
- **SNR range extended:** test levels are now 0, 5, …, 40 dB (9 levels); training range 5–40 dB. 0 dB stays outside the training range (extrapolation test). Regimes fixed in the protocol: stress 0–20, moderate 25–30, near-nominal 35–40.
- **Third noise type, `correlated_gaussian`:** noise in the 20 m bands (`B05`–`B07`, `B8A`, `B11`, `B12`) has Gaussian sd 1 px and in the 60 m bands (`B01`, `B09`) sd 3 px (`CORRELATION_SIGMA_PX` in `src/data/bands.py`), generated by FFT filtering of white noise and rescaled to the same nominal `N_b`. Verified: realised SNR within 0.035 dB of target; lag-1 autocorrelation 0.97 (60 m bands), 0.78 (20 m), 0.00 (native 10 m), matching theory. It addresses the finding that independent pixel noise is spectrally far from these smooth bands. It is an approximation of the resampling kernel, not a calibrated model.
- **Per-tile test noise:** `test_noisy_tile()` generates one noisy realisation per (tile, noise type, SNR), seeded `degradation_seed(0, tile, round(SNR·100))`, shared by every model; test patches are crops. `degradations` now has 432 rows (16 tiles × 3 types × 9 levels) holding the full parameter record as JSON; all 432 verified to reproduce from the stored tile statistics. The DB shrank from 33.5 MB to 1.5 MB. Training noise is still drawn on the fly per patch.
- **PSNR peak stored:** `tile_band_stats.peak` = 99.9th percentile of valid pixels per tile and band (a fixed 65535 peak would inflate PSNR).
- **Ship contrast-to-noise:** table `tile_ship_contrast` (contrast between ship pixels and open water 3–10 px away; `src/eval/contrast.py`). Per-pixel B04 CNR at 10 dB ranges from 0.49 (`panama`) and 0.58 (`rotterdam2`) to 5.09 (`marseille`), about a 10× spread. Caveat: `rome`'s contrast mixes river boats (water mask misses the river) with harbour ships, so it is unreliable.
- **Statistics utilities** (`src/eval/stats.py`, verified by `scripts/check_stats.py`): exact two-sided Wilcoxon signed-rank (all 2^n sign patterns, hand-verified cases), Holm correction, a cluster-robust 95% t interval (clusters = overlap groups) and a cluster bootstrap. Simulated coverage on data shaped like ours (13 clusters, one holding a quarter of the ships, nominal 95%): **cluster-robust 0.90, cluster bootstrap 0.88, naive ship-level bootstrap 0.12**. The clustered methods still under-cover by a few points because there are few, unequal clusters; the paper should say so. Primary interval: cluster-robust; bootstrap as sensitivity check.
- **Frozen protocol** `configs/protocol.json` (version 1): noise types and levels, SNR definition, valid-pixel rule, PSNR peak rule, regions, ship-instance counting rule, statistics plan, hypotheses H1–H3 with a proposed non-inferiority margin for H3 (global PSNR cost below 0.1 dB, open to revision before training), and the known limitations. Committing it before training gives a dated pre-specification.
- **Wording:** title changed from "under Realistic Noise" to "under Controlled Noise Degradation" (README, this file). Do not use "realistic" for the synthetic noise in the paper; describe it as controlled degradation spanning a stress regime and near-nominal levels.
- **Still not addressed:** the reference images are real and carry their own noise; noise is independent across bands; the shot fraction is an assumption; 16 scenes from one month; the delivered water mask fails for `rome`.

### 17. Evaluation harness and first reference results (2026-09-19)
**Code:** `src/eval/metrics.py` (per-band RMSE, NRMSE, PSNR with the per-band peak, SSIM, then SAM and ERGAS; regions all/ship/water/background; invalid pixels masked; per-ship `ship_nrmse` and `contrast_error`), `src/eval/baselines.py` (identity and per-band Gaussian smoothing), `src/eval/results.py` (results databases and `merge`), `scripts/check_metrics.py`, `scripts/eval_baselines.py`, `scripts/summarize_results.py`. Definitions are frozen in `configs/protocol.json`.
- **Verified** (`scripts/check_metrics.py`, all checks pass): SSIM equals a slow direct implementation; ERGAS, NRMSE and PSNR match closed forms on constant tiles; SAM is 0 for scaled spectra; invalid pixels do not change any metric; regions are consistent; perfect predictions give zero instance error and blurring raises it; merge copies runs, metrics and instance metrics and refuses a duplicate run name; on a real tile the **identity baseline's PSNR equals the analytic value from the SNR definition** (18.59 vs 18.59 dB at 10 dB, 38.59 vs 38.59 at 30 dB).
- **Results database split:** `runs`, `metrics` and a new `instance_metrics` moved to `db/results_schema.sql`; `db/reference.sqlite` is now purely derived (rebuilt without any guard). One results file per person or batch, merged later.
- **Run:** identity, Gaussian smoothing with sd 1 and 2 px, on 6 tiles (`toulon`, `brest1`, `rotterdam1`, `marseille`, `portsmouth`, `panama`; 708 ships), two noise types (gaussian, correlated_gaussian), SNR 0/10/20/30/40 dB; 60 conditions in about 25 minutes, results in `db/results_baselines.sqlite` (git-ignored).

Findings (fixed, untuned smoothers; six tiles; not a claim about learned models):
- **Global metrics hide ship loss even for a trivial denoiser.** Gaussian noise, smoothing sd 1: at 20 dB global PSNR improves by +7.3 dB while the ship region gains only +2.9 dB; at 30 dB global +0.9 dB but ship **−5.0 dB**. With sd 2 at 20 dB global is **+3.9 dB but ship −2.3 dB** (the sign flips). Per-ship contrast error at 20 dB and sd 1 is worse than the noisy input by +0.0099 (cluster-robust 95% CI [+0.0056, +0.0142]) although global PSNR rose 7 dB. Spectral distortion on ships also grows (SAM on ships at 40 dB: 1.08° identity versus 5.9° with sd 2). The gap ("ship lag", global gain minus ship gain) grows with SNR: about 0.6 dB at 0 dB SNR to about 6 dB at 30–40 dB. This is the phenomenon RQ3 is about; the harness detects it, and trained models must be judged the same way.
- **There is a crossover:** smoothing preserves ship contrast better than doing nothing only at 0 dB (difference −0.021, CI [−0.032, −0.010]); at 10 dB it is a tie; from 20 dB up it is worse, with a floor set by blur (about 0.016 for sd 1, 0.034 for sd 2), while the identity error keeps falling with SNR.
- **Independent noise flatters denoisers by about 5–6 dB.** At 10 dB smoothing gains +10.2 dB on independent Gaussian noise but +4.5 dB on correlated noise (0 dB: +10.9 versus +5.1). This confirms the step 14 concern and justifies keeping `correlated_gaussian` in every comparison; results on independent noise alone would overstate any denoiser.
- **Caveats:** only six tiles, so the cluster-robust intervals use few clusters (wide, and still slightly under-covering); the smoothers are fixed, not tuned, so they say nothing about the best achievable classical result (BM3D not run); the ship region is small (34,340 pixels in total), so ship PSNR is noisier than global PSNR; correlated noise here is an approximation of the resampling kernel.
